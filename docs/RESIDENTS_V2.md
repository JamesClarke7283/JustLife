# Residents with two-floor homes

This port retains stable Maya/Leo identities, street walks, friendship-gated visits and the original Juniper car. Friend houses have canonical ground-floor building records; the cottage and bungalow retain separate wall plans, floor finishes and furnishing arrangements. Two furnishings were moved clear of partition walls so complete friend-home saves pass the same strict layout validation as the player's house.

`LifeResidents.snapshot()` reads current resident transforms into detached data. `LifePhysicalSnapshot.capture()` includes that state alongside the actual household bodies, routes and canonical structure. `_prepare_loaded_world()` creates a separate resident service attached to its candidate world. `_adopt_loaded_world()` adopts and rebinds the world, household, traversal, meal flow and residents together only after reconstruction succeeds. A rejected candidate does not change the current resident service or its world. A saved current social action targeting an absent resident is rejected before adoption; later queued actions still use the normal presence check when they reach the front.

Canonical boarding uses `LifeTraversal.request()` and `advance()` for floor navigation, real stair gait, FIFO admission and safe exit clearance. Route preflight uses a separate traversal planner and reserves sidewalk positions with physical body clearance; passing residents cannot occupy a selected boarding endpoint. Actor transforms are not flattened to the ground before boarding. When the household reaches the car, the old lot's cached journeys are cleared before the destination is built. Full player-home records, finishes, stairs, openings and upper furnishings remain available for the return trip. Legacy public-venue saves preserve a validated canonical nested home layout independently of the current venue’s empty journeys, so a library save cannot flatten upper furnishings. Arrival occurs on the destination ground sidewalk.

Departure currently refuses while anyone owns a stair crossing. This refusal changes no action queue, stair ownership, food custody, body, clock or resident state. The notice asks the player to let the crossing finish before retrying. Automatic queued departure after a safe landing is not implemented.

`LifeTravelFood` runs existing supported-placement rules against a detached copy of the meal ledger. It checks every carried dish in household order, reserving earlier releases for later carriers. If placement is possible, the existing meal cancellation code performs the real release before boarding. Stair-owned food is kept with the Lifelet until the existing safe-landing release completes. The preview does not alter the live ledger or body. Travel's time advance remains in `travel` mode; the separate sanitation feature must defer physical accidents until visible live play resumes on the destination lot.

The car still uses hide/show boarding, and resident schedules remain simple with retained offscreen states rather than continuous offscreen simulation. This port does not claim a complete life simulator or a 10/10 visual rating.

Run `python3 tests/run_resident_v2_checks.py` to create a private source snapshot, disable editor/MCP services, set isolated `JUSTLIFE_DATA_DIR` and `XDG_DATA_HOME`, import it, and run the neighborhood, queue-presence, V2 producer/fresh-consumer, actual cooked-food custody and real stair-controller checks. The exact input hashes, logs, per-process exits and warnings remain in that snapshot's `evidence` directory. Test receipts use full-precision JSON so exact save/load comparisons are not weakened by rounded expectations.
