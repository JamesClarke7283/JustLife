# Original Juniper landing guard kit

Private static integration candidate, independently reviewed at7.5/10 for static art; full-game score unchanged7.2. Three material meshes each:1m span1188 triangles, post432 triangles. Source preserves editable pieces in juniper_guardrails.blend. Generator create_guardrails.py exports deterministic material order; it keeps span markers and a separate PostBase. Initial unsorted-order export and its source/log are preserved in initial_guardrails.

Span local+X is0..1m between post centers. Upper rail top1.0275m, post cap top1.076m; post bounding half-width.039m, half-depth.043m. Use a shared post per junction. The static fixture divides each run into equal segments no longer than1m and scales only the span length. It sets side lines x±.68m, lower cross-line z−.055m, leaves the upper landing exit open, and retains the complete .625m-half-width ×3.75m stair void. All guard footprints require real supported slab and navigation exclusion during integration. No floating rail is allowed when a floor has insufficient surrounding coverage.

The actual Forward+ test produced388 checks/0 failures and1400×1000 captures: four rotated assemblies, imported RailEnd joins, full post-footprint corner support, true floor-hole rays, supported upper landing, and adult/child-sized capsule queries against real guard triangles. A deliberately intersecting capsule confirms the clearance query detects an actual rail. These proxies prove neither full Lifelet clothing/body/head clearance nor locomotion, feet, occupancy, save/reload or public Build behavior. The cutaway image hides two slab meshes visually while retaining their physics solely to show the staircase below; it is not an unsupported placement claim.
