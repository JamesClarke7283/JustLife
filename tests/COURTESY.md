# Household courtesy regression

Run `python3 tests/run_courtesy.py` on Linux. The runner makes a new retained source snapshot under `dist/test-work/courtesy-check-*` and uses private XDG data, config, cache, temporary and JustLife save directories. It never reads the player save folder or invokes a native pointer command. Its source manifest includes every copied script, asset, runner and fixture. Each phase also pins the existing saved JSONs and rejects an unexpected overwrite.

The first phase resumes the exact earned four-member crowd checkpoint without an intermediate save. It checks the original Ellis/Morgan pair and route identity, the complete original passing-path endpoints and physical arrival at the chosen holding place. The coordinate of a valid sidestep is free to change when selection improves. The next phase records real retreat and hold states, and a separate process loads both paused and resumes to actual food pickup. Mutation controls cover cancellation, expiry, repeated target/navigation reconciliation, Build Move/cancel, prior resource reservations, instruction identity, malformed saves and legacy v1 reading. A declared arrived-waiter component fixture is saved and loaded in another process. The test keeps the .72 m all-visible spacing assertion and separately reports household-versus-visible and pedestrian-only spacing.

The natural continuation uses normal controller `_process(.05)` calls with a yielded process frame after each call. Its starting needs, wallet, clock, autonomy, action progress and social rewards are not edited. Named component tests explicitly construct a saved arrived resource wait or expire only the bounded courtesy fact; those tests are not natural progression evidence. Build placement uses public buttons and the production placement signal; pointer picking and preview are outside this headless test.

The 45,901-byte `fixtures/courtesy_first_crowd.json` is the actual first-stall named save from the three-day household review at commit `9dcbd52bcdd9da387a64e03ba8a2289856e49822`, game minute 1424.399999999954. Four Lifelets were created through the public creator and moved into Willow Cottage with default funds. An upper floor, staircase and bed were purchased through production Build controls. Autonomous actions and directed dinner/homework produced this crowd naturally. No actor positions or needs were injected. The fixture intentionally keeps old v1 journeys so current legacy admission is exercised.

The courtesy writer uses outer journey v2; v1 is accepted only without a courtesy fact. The original donor and beneficiary journey identities, destinations, action queues and paid/progress fields must stay intact. Explicit replans can allocate new ordinary route identities for other household members. Build reconciliation may project saved food position arrays into the engine's Vector3 precision; tests compare that declared typed geometry exactly while keeping authoritative serving counts, ownership and progress exact. No epsilon is applied to those scalar fields.

The local search chooses once per advancing controller step, comparing successful pairs by donor retreat plus returned beneficiary path length. It keeps the first twelve candidates, first two eligible peers per candidate and at most 24 hypothetical route queries; exact ties retain candidate order then peer ID. The initial hold expires after at most 60 game minutes. The score excludes later donor travel, future stairs, duration and waiting; more route queries and fairness remain practical limits. This is a bounded local recovery mechanism, not proof that every house layout remains live. The original three-day review remains separate from these targeted checks. The extracted wrapper requires its own combined-source execution before claiming a clean end-to-end run.
