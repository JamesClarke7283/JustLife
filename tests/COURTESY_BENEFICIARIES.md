# Stair clearance and ordinary walking courtesy

Run `python tests/run_courtesy_beneficiaries.py` on Linux. `--group stair` and
`--group walk` run the two bounded groups independently. The runner copies the
explicit runtime manifest and named tests into a new private project, disables
autoload/editor integrations there, isolates XDG/config/cache/tmp/saves, retains
each log and receipt, and rejects errors, source drift or overwritten existing
saves. Each owned process has a 420-second cap (`--timeout`), raised from 180 s after the iteration-50 clock change made the walk-controls phase exceed the old limit. No renderer or native pointer is
used; synthetic public buttons/signals and ordinary `.05` controller calls are
labeled in the evidence. There is one yielded engine frame per controller step.

The stair group starts from a genuinely played household whose ordinary bed
approach obstructs an already owned stair-clear exit. It covers natural donor
retreat/hold and safe exit, actual named phase saves and separate fresh loads,
normal protected-action cancellation, strict version/kind validation, navigation
rebuild, earlier wait/stair reservations, conservative live-vs-restored clearance,
no usable anchor and safe expiry. Its held-food case is an explicit ledger
component followed by real protected movement and one physical setdown; it does
not claim a natural food pickup.

The walk group first replays the genuine late bathroom checkpoint. Morgan's
empty-queue route235 must reach its original destination, retire normally, and
the donor must move on a later ordinary step with its original instruction.
Actual retreat/save/fresh coverage is generated from that same original route.
That short original route finishes before a hold phase, so a separate declared
scenario starts from the earlier crowd fixture: public Cancel followed by a new
ground-walk command to the prior meal target, then naturally observed hold and
fresh continuation. This is a new player instruction, not the original bathroom
recovery. Both generated slots are then kept as private evidence.

Mutation controls cover same-destination requests, unrelated Build/replan,
changed destination, public cancellation, a real new action, excluded floor
transfer/resource/custody ownership, and immediate public named saves. The
version-1/2 cases use ordinary activity donors. Idle actors and furnishing wait
owners remain excluded as donors. A separate [current-floor regression](CURRENT_FLOOR_CONTRACT.md)
covers the new version-3 pair: an unowned future stair approach yields to a
housemate returning to an available furnishing while retaining its FIFO place.

The comparison boundaries are explicit. JSON INT identities use only the
existing named integer fields, vectors/yaw use their actual engine projection,
and restored action progress uses decoded elapsed/duration. The replacement
save may adopt its observed live command into the formerly cached walk intent.
Harmless Build may allocate exactly two fresh, unique ordinary nonparticipant
route IDs; donor/beneficiary IDs and all other compared facts remain exact.
The custody continuation projects only its unchanged hosted batch position by
the existing host transform. No epsilon or blanket numerical normalization is
used in these expected-state comparisons.
