# Owned portion approach

Run `python tests/run_owned_meals.py` on Linux. Godot must be available as `godot`. The runner creates a retained `dist/test-work/owned-meal-check-*` snapshot, private XDG/config/cache/temp/save directories, and removes editor addons/autoloads from that test copy. It does not read or overwrite player saves. It retains import/game logs, source hashes, result receipts, and every prior/new test save hash; each process is capped at 300 seconds.

The source fixture `fixtures/owned_meal_approach.json` is the exact final named save from a failed capped four-member composed review. It contains a real publicly created/furnished household, actual earned needs/actions/food and a protected stair traveler. The original three-day review remains failed; this smaller test does not replace it. Fixture SHA256: `161caa5c7a0e90153018b61288d7898537c49c18bc5180fd66b54ab24fe0f069`.

The natural producer publicly loads this slot, verifies ten paused calls, then uses ordinary `_process(.05)` calls with one yielded process frame each. It follows Ellis's actual owned plate approach into physical arrival and eating, creates new public named saves during the reached approach and eating phases, and checks one completed portion, unchanged approach/action identities, no early payment/progress and exact eligible nourishment. It injects no character state, needs, funds, clock, positions or completion.

A separate process publicly loads each new save, preserves paused state and completes only its remaining real serving. Actor/vector values use the engine's explicit typed projection. Action `progress` uses the reader's existing exact formula `clampf(decoded elapsed / decoded duration, 0, 1)`; all other action fields and the authoritative food ledger remain exact. The independently serialized progress scalar can decode one ULP away from that derived value. Raw load differences are retained; no epsilon is used. Every resumed nourishment step is checked against the decoded actual portion and real elapsed interval.

The component phase uses the real meal service/ledger with explicitly supplied controller-arrival callbacks. It covers meal target aliases, partial paid state, another urgent need, expired/missing/foreign portions, later player instructions/direct cancellation, invalid endpoint re-resolution and waited-resource replacement. These component metadata/need controls are distinct from natural walking evidence. Existing active meal recovery, expiry and cancel/resume checks are retained, followed by the existing autonomy policy suite.

All interaction is through synthetic engine control signals or declared component methods. This is headless simulation/save coverage, not pointer picking, rendered presentation, universal path recovery or sustained household attendance proof.
