# Test guide

Run commands from the project root with Godot available on `PATH`. Use an existing local `TMPDIR` when temporary storage is limited; `dist/test-work` is ignored build storage. The maintained runners create isolated project copies and private save/user-data folders. Read each runner's options before using a fixture directly.

Before running direct Godot fixtures, point `JUSTLIFE_DATA_DIR` and `XDG_DATA_HOME` at separate private temporary directories to keep test saves and settings apart from your game.

The Linux-only activity-flow runner accepts `--source /path/to/checkout`. It combines the existing dependency manifest with its explicit test and fixture inputs, copies them into a private project, strips plugin/autoload configuration there, and isolates save, data, config, cache and temporary paths. Its six phases cover natural recovery, admission, retry components, public Pause/Build, public Save during an observed obstruction and a fresh process loading that generated save. The save pair shares the original 600 advancing-call budget: 107 before saving and at most 493 after loading. The runner compares all 107 producer rows with its natural prefix, validates fresh phase reports against terminal counts, and verifies input and pre-existing save hashes.
