# Test guide

Run commands from the project root with Godot available on `PATH`. Use an existing local `TMPDIR` when temporary storage is limited; `dist/test-work` is ignored build storage. The maintained runners create isolated project copies and private save/user-data folders. Read each runner's options before using a fixture directly.

Rendered fixtures require a display AND an otherwise-idle machine: concurrent rendered runs or heavy GPU work stall the social timing windows (observed as intermittent "walk from shower to neighbor" timeouts; four consecutive exclusive runs pass while interleaved runs fail). Some grants set needs, disable autonomy or invoke public button callbacks directly. They exercise the stated paths, not unscripted whole-game play or a general quality score. Individual assertions are not additional gameplay scenarios.
Since the iteration 50 clock change, Normal speed advances one game minute per real second; the busy-resource, pedestrian and home-visit harness windows were widened in iteration 57 to observe the same rules at that pacing (their earlier budgets could not see a 30-minute wait, two walker cycles or a 360-minute stay).

The Linux-only activity-flow runner accepts `--source /path/to/checkout`. It combines the existing dependency manifest with its explicit test and fixture inputs, copies them into a private project, strips plugin/autoload configuration there, and isolates save, data, config, cache and temporary paths. Its six phases cover natural recovery, admission, retry components, public Pause/Build, public Save during an observed obstruction and a fresh process loading that generated save. The save pair shares the original 600 advancing-call budget: 107 before saving and at most 493 after loading. The runner compares all 107 producer rows with its natural prefix, validates fresh phase reports against terminal counts, and verifies input and pre-existing save hashes. The initial maintained extraction passed 226 assertions; these remain focused checks rather than an endurance, attendance, rendering or release gate.

The exploratory `--suite dense_meals --timeout 900` retains a known late-dinner checkpoint failure. Read [the dish-placement review](../docs/REVIEWS/iteration_14_dish_placement.md) before interpreting its results. Later repairs and their narrower evidence remain in their respective reviews. Logs, screenshots, traces and manifests are local evidence; failures and warnings must remain visible when reporting a result.

[Release verification](../docs/RELEASE_VERIFICATION.md) records actual exported-binary checks and separates them from source tests. [Independent reviews](../docs/REVIEWS/) record acceptance decisions and remaining visual or behavioral limits.
